# Design: Process #3 — Generate Predict PM Reports

**As-is today**: [`dataiku/recipes/recipe_predict_pm_reports.py`](../../dataiku/recipes/recipe_predict_pm_reports.py)
already wraps `uat_08_generate_pm_reports.py --mode non_uat --predict`, and `uat_08` already implements
the full Decile-Aware Predict Reveal mechanism required by prompt D3:
- Gate 1 — market registered in `models/paso_6_model_strategy_decision.json` (`_check_routing_json`)
- Gate 2 — model SHA-256 matches the approval-time manifest (`_check_model_drift`)
- Gate 3 — per-row score bucket must be in an `AUTO_MERGE`/`AUTO_NO_MERGE` approved bucket
  (`_load_decile_automation` + `_maybe_reveal_predict`)
- Fail-safe degrade-to-blind on any gate failure, with the reason recorded in `Report_Info`
  (`model_drift_detected`, `automation_source`, `n_auto_revealed`)
- `DECISION_SOURCE=AUTOMATED` set only on revealed rows; all other rows stay blank

**This already satisfies D3 in full.** No functional change to `uat_08`'s gating logic is proposed.

## Only gap: BACKLOG-007 (missing `--reports-decile-dir` CLI flag)
`uat_08_generate_pm_reports.py` reads `uat/reports_decile/{slug}_decile_combined_analysis.csv` via a
path relative to the framework root, but has no `--reports-decile-dir` override flag (unlike
`--extracts-dir`, `--output-dir`, `--models-dir`, which all exist). In a Dataiku deployment where
`uat/reports_decile/` is not physically present under the Project Library checkout (it's `.gitignore`d,
generated by local UAT runs), the predict recipe's reveal gate will find the CSV missing and — per the
existing fail-safe design — **correctly degrade to blind**, but silently, with no way to point it at a
Managed Folder holding a fresher copy of that CSV.

## Proposed fix (future implementation)
1. Add `--reports-decile-dir PATH` to `uat_08_generate_pm_reports.py`, following the exact same
   override pattern already used for `--extracts-dir`/`--models-dir` (single `if args.reports_decile_dir:`
   branch overriding the default `ROOT / "uat" / "reports_decile"` path).
2. `recipe_predict_pm_reports.py` gains one more Managed Folder input, `uat_reports_decile` (already
   listed in `docs/DATAIKU_DEPLOYMENT_GUIDE.md`'s folder table but not yet wired into the recipe), and
   passes `--reports-decile-dir <path>`.
3. Once [AUTOMATION_POLICY](../contracts/AUTOMATION_POLICY.schema.yaml) exists, this flag could instead
   point at wherever the policy derivation script's *source* decile CSVs live (same folder, no change
   needed) — the two efforts are complementary, not conflicting.

## Explicitly out of scope
- No change to which buckets get approved, no change to blindness rules, no change to `DECISION_SOURCE`
  semantics (restriction L: "no reveles scores en buckets no aprobados").
